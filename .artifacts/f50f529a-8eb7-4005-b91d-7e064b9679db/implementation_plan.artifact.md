# Before/After Comparison Audit & Optimization Plan

This plan addresses the performance issues in the comparison slider and the lack of visible quality difference between the original and compressed images.

## User Review Required

> [!NOTE]
> The optimization involves disabling image caching for the comparison viewer to ensure that the actual compressed bytes are rendered, which may slightly increase loading time for that specific screen but guarantees accuracy.

## Proposed Changes

### 1. UI Component Optimization (`feature/compare/view`)

#### [MODIFY] [ComparisonView.kt](file:///C:/Users/User/AndroidStudioProjects/LumoraCompress/app/src/main/java/uz/kmax/compress/feature/compare/view/ComparisonView.kt)
- **Object Pooling**: Move `Matrix` and `Paint` allocations out of `onDraw` and `drawFitBitmap`.
- **Pre-calculation**: Calculate the scale and translation matrices only when the bitmaps are set or the view size changes.
- **Rendering Performance**:
    - Replace `invalidate()` with `postInvalidateOnAnimation()` in `onTouchEvent` for smoother 60 FPS interaction.
    - Optimize `onDraw` to use pre-calculated matrices.
    - Ensure `clipRect` is used efficiently to avoid overdraw.

### 2. Image Loading Accuracy (`feature/compare/fragment`)

#### [MODIFY] [CompareFragment.kt](file:///C:/Users/User/AndroidStudioProjects/LumoraCompress/app/src/main/java/uz/kmax/compress/feature/compare/fragment/CompareFragment.kt)
- **Cache Invalidation**:
    - Configure Coil `ImageRequest` with `memoryCachePolicy(CachePolicy.DISABLED)` and `diskCachePolicy(CachePolicy.DISABLED)` for both original and compressed images.
    - This ensures Coil does not return a cached original bitmap when requesting the compressed version.
- **Visual Fidelity**:
    - Explicitly disable `crossfade` in comparison requests to prevent blending that might obscure quality differences.
    - Ensure `allowHardware(false)` is maintained for compatibility with `Canvas.clipRect`.

### 3. Navigation & Data Flow

#### [VERIFY] [CompareViewModel.kt](file:///C:/Users/User/AndroidStudioProjects/LumoraCompress/app/src/main/java/uz/kmax/compress/feature/compare/viewmodel/CompareViewModel.kt)
- Confirm that the `compressedUri` passed to the fragment points to the latest output file generated by the engine.

## Verification Plan

### Manual Verification
1. **Performance**: Drag the comparison slider rapidly.
    - **Expectation**: Movement should be perfectly fluid (60 FPS) without stutter or jitter.
2. **Quality**: Compare an image with high compression (Low quality).
    - **Expectation**: Compression artifacts should be clearly visible on the "After" side of the slider.
3. **Accuracy**:
    - Verify that the "Before" side displays the original resolution and size.
    - Verify that the "After" side accurately represents the compressed output.
4. **Lifecycle**: Rotate the screen while on the Compare screen.
    - **Expectation**: View state (slider position) should be preserved or reset correctly without crashing.
